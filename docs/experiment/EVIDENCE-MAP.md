## Recorded limits

These limit the claims above; none is closed by INC-14.

- **L1 — throwing consumer callback.** A throwing `onEvent` consumer in `apps/web/src/api/sse-client.ts` has no automated test: the client deliberately rethrows, and Vitest reports that as an unhandled error. Only INC-08's live validation (M) exercised it. Callback-error coverage is not claimed to be complete.
- **L2 — seeded, not power loss.** Restart-recovery tests seed a non-terminal response into the file and then restart. They do not kill a process mid-write or simulate power loss.
- **L3 — jsdom, not a browser.** INC-13 component tests run in jsdom with stubbed `fetch`. Real-browser evidence for the UI rows is manual: the INC-09 smokes and the evaluator's real-browser probes. No automated real-browser end-to-end test exists.
- **L4 — workflow ledger.** The git-ignored `agents/TEMP/chat-poc/coding-flow-state.md` phase ledger is stale and was deliberately not repaired. Tracked plan/log progress is not proof of full Rosetta phase conformance.
- **L5 — transcript gap.** During INC-13 the host reported failed transcript writes (ENOSPC). Complete transcript evidence is not claimed for that period.
- **L6 — indirect-only coverage.** `apps/api/src/config/env.ts`, `apps/web/src/config/env.ts` and `apps/web/src/api/http-client.ts` have no dedicated test files. The API env parser runs in the real-process tests, `http-client.ts` runs under the provider and App tests, and the web env parser was checked only in INC-08's validation (M).
- **L7 — no lint.** No lint or format tool exists (A-014); typecheck, tests, build and `git diff --check` are the validated gates.

### Note on AC-015

AC-015 cannot be satisfied by product code or a product test. The fixed criterion names the separate GOV-004 demonstration, not a new recovery run on EXP-002's final implementation. The actor initially left this row out-of-product to preserve isolation. After the actor stopped, the evaluator reviewed the existing separate reports and recorded the failed complete-recovery outcome without changing the criterion or supplying governance artifacts to the actor. Technical planning was reconstructable, but human approval and the authorized next action were not reliably recoverable. This is a mixed governance result, not a chat application defect. Tracked plans and current documentation improve technical legibility; they do not prove approval persistence.

INC-14 did not read, diff or check out any GOV-004 ref or artifact; its fresh clone used `--single-branch --no-tags`. A fresh clone that installs, typechecks, tests and builds (AC-001) proves application reproducibility only, not fresh-agent recovery.
